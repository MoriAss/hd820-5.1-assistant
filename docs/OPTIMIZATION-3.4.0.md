# v3.4.0 优化记录

本版重点减少持续播放时的CPU和内存分配，补上首次使用诊断、配置恢复及发布验证。没有改变AC3码率、声道增益、低音滤波响应或已验证的USB输出缓冲。

## 音频处理

旧的声道转换对每个采样点重复解析同一个格式GUID，每包还重建多组声道映射。现在缓存格式标识，在已允许的5.1/7.1布局内直接映射。128,189条参考断言通过，所有输出字节与旧实现一致。在本机一次2000包、每包480帧的专项量测中，该转换步骤为685ms→29ms；这不是整条音频链路的速度或延迟。

采集、声道映射和重采样改用预留工作区；各步骤显式传递有效样本数，数组尾部不参与编码。编码器使用有界字节缓冲池，写线程完成前不归还，丢弃、断管及退出路径都检查回收。仍然复制调用者提交的有效数据，避免生产者覆盖尚未发送的声音。

6000个480帧音频包的“重采样＋float转byte”专项中，线程分配约209MB→8KB，Gen0回收33→0，输出保持一致。该数据只覆盖上述组件；真实程序CPU的独立观察见下节，硬件听感仍需另行验证。同步器的分块边界、低音处理、极端浮点、池化溢出、in-flight缓冲和真实六路FFmpeg输出都有回归。

FFmpeg诊断输出改为固定字符块读取并限长；无换行长输出也受到限制，避免错误程序的诊断流持续占用内存。

## 本机后台观察

同一台机器、同一份FFmpeg 4.3.2，分别采集旧版与新版约60秒后台静音运行。助手CPU按单个逻辑核心100%计算，从5.77%降至2.49%，约下降57%；Gen0/Gen1/Gen2回收增量从60/8/4降至2/1/1。两段均未出现新增欠载、输入丢帧、输出丢包或输出空队列事件。

这只是两次先后进行的静音采样；旧进程已运行较久、新进程刚启动，整机负载也可能变化。回收增量来自遥测首末时间点，旧版2秒、新版5秒采样；不将工作集差异当成内存节省证据，也不将这些数字作为游戏性能或硬件实听结论。

新版已通过已注册登录任务的手动Run启动，核对了EXE哈希、原偏好、递增音频计数，以及关闭退托盘后同进程的`--show`恢复。运行中的“无声检查”已返回FFmpeg、入口和自启结果。没有为本次验证重启电脑或要求用户试听；本机原生截图接口返回空白帧，界面排版另用隔离控件渲染图核对。

## 使用与配置

- 新增“无声检查”和`--diagnose`，检查FFmpeg运行与AC3/SPDIF能力、静音载体、虚拟入口格式和本程序位置的自启状态。它不播放声音、不切换设备，报告省略个人路径和设备ID。
- 首次物理数字输出需手动选择；通用USB设备名不能证明它是HD820。已有有效选择继续使用，失联时不会自动切到另一块声卡。
- 拖动设置合并写入，正常退出刷盘；保留上一份有效设置，损坏时可恢复并明确提示。无效原件留存到本机日志目录。
- 修复深目录中坏配置归档和原子写入临时名过长的问题。更深的同一测试路径中旧实现3项失败，修复后13项UI优化回归全部通过；没有修改系统长路径开关。
- 修复下拉框和滑杆的方向键处理，减少静音电平的重复绘制及后台状态文字构造。前台遥测默认2秒、后台5秒。
- 停止先标记忙碌并禁用重复操作。资源清理仍是有界同步等待，不宣称已实现全异步停止。

## 测试与发布

完整测试结果见[验证摘要](VALIDATION-3.4.0.json)，云端运行结果见仓库Actions。真实FFmpeg解码检查继续使用原有频率、幅度、串音和低音阈值，新增池化PCM以及UTF-8带/无BOM路径；完整回归使用FFmpeg 9.0.2，并以生产中的4.3.2另做真实池化六路解码兼容检查；不因优化降低信号质量门限。

公开仓库新增可复用打包和教程生成工具。程序包绑定已测EXE、源码、静音资源、构建脚本和测试定义的哈希；附文件清单和SHA256。同一组输入字节生成一致ZIP，但不承诺不同机器编译的EXE字节相同。GitHub CI的程序artifact也包含完整新手教程。

此前长时间运行曾记录替补静音和输入丢帧。本轮减少了已量测的软件开销，但尚不能证明已经解释或消除用户听到的所有卡顿；没有USB/模拟回采或端到端延迟测量，普通5.1与Atmos对象音频的边界不变。
